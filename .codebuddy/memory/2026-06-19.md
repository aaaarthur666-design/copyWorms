## Level_03 集成 PixelGlitch
- 触发时机：`_on_lingnan_combat_complete()` 末尾（CYBER_CITY 状态设置后）调用 `_start_pixel_glitch()`
- 强度驱动：`_process` 中根据玩家与 `_memory_echo_2_node` 的距离动态计算
  - 距离 ≤ 200px → intensity = 1.0（满强度）
  - 距离 ≥ 1000px → intensity = 0.0（无效果）

- 停止时机：`_stop_cyber_elements()`（觉醒时）+ `_full_cleanup()`（关卡结束）
- 与 erosion_vignette.gdshader 无关，该 shader 属于 Level_04 侵蚀系统

## 修复 Level_03 → Level_04 关卡切换失败
- 根因：`_emit_level_complete()` 只 emit LEVEL_COMPLETE 事件，缺少双模切换回退（Level_02 有 `_is_loaded_under_main_entry()` 判断 + `change_scene_to_file` 回退，Level_03 没有）。非 MainEntry 托管时事件无人接收，关卡永远切不过去。
- 修复：Level_03.gd 的 `_emit_level_complete` 对齐 Level_02 模式 —— emit 前加 `gui_release_focus()` + `force_unblock_all()` + `_full_cleanup()`，然后判断 `_is_loaded_under_main_entry()`，无 MainEntry 则直接 `change_scene_to_file(next_path)`。
- 新增辅助函数 `_is_loaded_under_main_entry()` 和 `_disconnect_input_manager()`（对齐 Level_01 关卡退出三件套）。
- `_exit_tree()` 改为调用 `_disconnect_input_manager()`；`_full_cleanup()` 加入 `_disconnect_input_manager()` 并移除 no-op `unblock_input("关卡3清理")`。
- 未触碰觉醒演出、EndingPrompt、Enter 触发、互动/叙事逻辑。

## 修复 set_input_as_handled null 崩溃（上一轮双模切换的副作用）
- 现象：`Cannot call method 'set_input_as_handled' on a null value`
- 原因：`_emit_level_complete()` 加的 `change_scene_to_file` 回退会**同步释放当前场景**，`_input()` 紧接着调用 `get_viewport().set_input_as_handled()` 时 viewport 已为 null。
- 修复：`_input()` 的 LEVEL_END_TRANSIT 分支调用 `_emit_level_complete()` 后用 `var vp = get_viewport(); if vp: vp.set_input_as_handled()` 安全判断。
- **教训**：`change_scene_to_file` 同步释放场景，调用后不得再访问场景树/viewport，任何后续代码都需 null 防御。
